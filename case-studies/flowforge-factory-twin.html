THE PLANNING GAP

看得到設備，不代表看得到流量代價

當 Assembly 與 Packaging 分隔、物料路徑交錯時，靜態 3D 佈局不容易比較移動距離、WIP、產能與 AGV 阻塞之間的取捨。

佈局決策難比較

同一製程順序下，layout alternative 的物流距離和擁塞可能不同，需要把情境放進同一個比較基準。

產能受多個假設牽動

班次、需求、cycle time、OEE 與 AGV 車隊共同影響 throughput、達成率、WIP 與瓶頸。

規劃結果要交給工程工具

除了瀏覽器裡的模擬畫面，還需要可檢視的 OpenUSD scene structure、variants 與設備 metadata。

PRODUCT & ENGINEERING

讓決策視圖與工程資料保持連結

FlowForge 的核心不只是做一個 3D 看板，而是把使用者可調的規劃假設、模擬結果與 OpenUSD 場景結構放在同一個可說明的原型裡。

瀏覽器決策層

原生 HTML／CSS／JavaScript 與 Canvas 動畫呈現產線、輸送帶、AGV 與工件；切換 layout、需求與 fleet 後，可在簡化模型中比較輸出與交通情境。

OPTIONAL PHYSICAL AI LOOP

把 AI 建議放在人工核准之後

EdgeTwin AI Agent 是附加的技術展示：由模擬 twin 產生精簡 telemetry，再取得有界的 layout／派工建議；操作員明確審閱後才套用到目前 demo。

公開 GitHub Pages：deterministic fallback

靜態頁面可示範建議流程與 fallback，不代表每次都連到 live Nemotron，也沒有接上實際 Jetson 或工廠設備。

Live inference：需 server-side proxy

若啟動 Python proxy，才可由伺服器端呼叫 Nebius Token Factory 上的 NVIDIA Nemotron。API key 留在伺服器端；建議仍須由人審核，不是設備控制命令。

VALIDATION & LIMITS

原型能展示流程，現場驗證仍是下一步

目前可檢視

  • 瀏覽器 demo 的 layout comparison、簡化離散模擬與 AGV 情境。
  • 公開 OpenUSD stage、variants、references／payloads 與設備 metadata。
  • OpenUSD CLI / stage evidence 與 Windows RTX validation checklist。

目前不宣稱

模型是 deterministic simplified discrete simulation，不能取代正式工業模擬或安全驗證。未接現場 MQTT／OPC UA／Jetson；RTX USD Composer／Omniverse Kit runtime 驗證仍待在相容環境完成。
